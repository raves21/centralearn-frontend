## Project overview

`centralearn-frontend` is a Learning Management System (LMS) frontend: React 19 + TypeScript + Vite, with a domain-driven folder structure. It has two main areas reached via TanStack Router pathless layouts: an **admin panel** (`/admin-panel/*`, managing departments, programs, courses, sections, semesters, classes, instructors, students, admins) and an **LMS** (`/lms/*`, classes/announcements/contents/members/grades/dashboard for instructors and students).

## Commands

Package manager is `bun` (see `bun.lock`).

- `bun install` — install dependencies
- `bun run dev` — start dev server (port 5174)
- `bun run build` — typecheck (`tsc -b`) then production build via Vite
- `bun run lint` — ESLint
- `bun run preview` — preview production build

There is no test runner configured in this project.

## Architecture

### Path alias
`@/*` maps to `./src/*` (configured in both `tsconfig.app.json` and `vite.config.ts`). Always import via `@/...` rather than deep relative paths for anything outside the current domain.

### Domain-driven structure (`src/domains/<domain>/`)
Each domain (e.g. `classes`, `courses`, `students`, `instructors`, `assessmentMaterials`, `studentAssessmentAttempts`, `chapters`, `chapterContents`, `auth`, ...) owns its own:
- `api/queries.ts` and `api/mutations.ts` — TanStack Query hooks wrapping the shared `api` axios instance
- `components/` — domain-specific components (often split further, e.g. `adminInstructorView/` vs `studentView/` for role-specific rendering of the same feature)
- `types.ts` — domain TypeScript types
- `stores/` — optional Zustand store for domain-local state (e.g. `useManageAssessmentMaterialsStore.ts`)

Domain logic, types, and API calls should stay within their own domain folder rather than leaking into `src/components` or `src/utils`.

### Networking
`src/utils/axiosBackend.ts` exports a shared `api` axios instance: `baseURL = ${VITE_BACKEND_URL}/api`, `withCredentials: true` (cookie/session-based auth, not bearer tokens). Backend responses are wrapped in an envelope; query functions unwrap with `const { data } = await api.get(...); return data.data as T`.

### Routing (TanStack Router, file-based, `src/routes/`)
- Route tree is generated by the `@tanstack/router-plugin` Vite plugin (`autoCodeSplitting: true`) — don't hand-edit generated route trees.
- `_protected` and `_unprotected` are pathless layout routes (`route.tsx` at each level) gating auth.
- `admin-panel` and `lms` are the two protected sub-trees.
- Dynamic segments follow TanStack conventions: `$id` for path params, and a trailing `_` on a segment (e.g. `$studentId_`, `$classId_`) marks a route that intentionally does *not* nest under its non-underscored sibling's layout — used here for "flat" pages like edit/enroll/assign screens that shouldn't inherit a parent detail-page layout.
- Search-param validation failures are handled via `useHandleSearchParamValidationFailure` and the `SearchSchemaValidationStatus` type.

### Auth & role gating
- `Role` enum (`superadmin | admin | instructor | student`) and `User`/`CurrentUser` types live in `src/utils/sharedTypes.ts` / `src/domains/auth/types.ts`.
- Current user is fetched via `useCurrentUser()` (`domains/auth/api/queries.ts`, query key `["currentUser"]`, `neverRefetchSettings`) and can be read/written directly from the cache via `getCurrentUser()`/`setCurrentUser()` in `domains/auth/functions.ts` (useful outside React, e.g. in route loaders or axios interceptors).
- Pages restrict access with the `useRouteRoleGuard({ allowedRoles })` hook, which redirects to `/` if the current user's role isn't allowed. Apply this at the top of role-specific route components rather than duplicating redirect logic.

### State management
- **TanStack Query** for all server state — one query/mutation hook per operation, colocated in the domain's `api/` folder. `src/utils/queryClient.ts` holds the shared `QueryClient` plus shared option presets like `neverRefetchSettings`.
- **Zustand** for client-only state that doesn't belong in the URL or query cache — either global (`src/utils/stores/useGeneralStore.ts`) or domain-scoped (`domains/<domain>/stores/`).

### UI components
- `src/components/ui/` — shadcn/ui primitives (Radix-based, "new-york" style, no Tailwind prefix; see `components.json` for the shadcn config, including a custom registry `@wds`). Generate/update these via the shadcn CLI rather than hand-rolling new primitives.
- `src/components/shared/` — generic reusable components across domains (e.g. `GlobalDialog`, `LoadingComponent`).
- `src/components/layout/` — app shell (`SidePanel`, `TopPanel`, `Providers`).
- Styling is Tailwind CSS v4 (via `@tailwindcss/vite`); prefer utility classes and existing shadcn components over new custom CSS.

### Forms & rich text
- Forms: React Hook Form + Zod resolvers (`@hookform/resolvers`).
- Rich text editing: Tiptap (`@tiptap/react`, `starter-kit`, `extension-placeholder`, `extension-text-style`), with a shared `TiptapSelector` type (`src/utils/sharedTypes.ts`) enumerating supported toolbar actions.
- File/media attachments follow the `FileAttachment`/`TextAttachment` shapes in `src/utils/sharedTypes.ts`.

### Pagination
List endpoints follow a Laravel-style pagination envelope (`PaginationProps` = `links` + `meta`, with `PaginatedQueryParams` for `page`/`searchQuery`/`filters` on the request side) — reuse these shared types rather than redefining pagination shapes per domain.
